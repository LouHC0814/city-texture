# 城市纹理 · City Texture

**在同一公里尺度下，观察两座城市的道路纹理。**

一个正在开发的人文地理交互项目。当前 v0.6 内置南京、苏黎世和伯尔尼的真实 OpenStreetMap 道路与建筑轮廓，可任取两座进行同尺度对照、连动探索、几何分析、观察卡导出与离线样本包导入。程序为独立实现的原生 HTML / CSS / JavaScript，没有运行时第三方依赖，也不需要账号、密钥或地图瓦片服务。

![桌面实测截图（v0.3 界面）](docs/桌面预览.png)

## 直接下载使用（v0.6.0）

打开 **[最新 Release 下载页](https://github.com/LouHC0814/city-texture/releases/latest)**，在页面下方 **Assets** 下载 **city-texture-v0.6.0-offline.zip**。完整解压后，双击 **打开城市纹理.html**。

也可下载 **city-texture-v0.6.0.html**，用 Chrome / Edge 打开。无需安装 Node.js、Python 或其他依赖，断网可用。详细步骤见 [中文使用说明](docs/使用说明.md)。GitHub 自动提供的 Source code 是开发用源码包。

## 如何体验

除了上面的 Release 成品，也可以下载仓库源码 ZIP 并完整解压，用 Chrome 或 Edge 打开 `dist/index.html`。不需要安装依赖。

已有 Node.js 22 或更新版本时，也可以运行：

```text
npm start
```

打开终端提示的 `http://127.0.0.1:4173`。开发服务器只监听本机。此版本未部署在线站点。

生成可以单独传递的 HTML：

```text
npm run build:standalone
```

输出为 `.runtime/城市纹理-第六阶段预览.html`。该文件包含全部道路、建筑样本与脚本，不需要服务器。

## 如何移动和保存观察位置

拖动任意一张地图，两侧会连动平移；两座城市采用相对各自样本中心的相同东/北公里位移，不是跳到相同经纬度。点“居中”只重置位置；点“重置”恢复城市、尺度、筛选和位置的默认值。

键盘操作：Tab 聚焦地图后，用方向键移动，每次移动窗口宽度的 10%；Home 回到样本中心。手机可以直接拖动地图，从地图之外的位置滚动页面。

点“复制当前比较”得到一段以 `#v=3` 开头的视图参数，包含当前图层。另一位使用者需要拥有支持相同城市的预览文件，再点“恢复视图”粘贴。**这不是公开网页链接，不需要复制本机文件路径。** 在线地址里的同格式片段也可粘贴，但应用只解析参数，不会打开该地址。旧 `#v=1` 参数恢复到样本中心，`#v=2` 保留平移位置；二者均保持原来的仅道路图层。

## 如何保存整次观察

点“保存比较”下载一个比较项目 JSON，里面包含当前视图、选中的内置样本和所有导入样本。下次打开程序后点“打开比较”，选择文件、查看预览，再点“打开这份比较”，就能接着观察，不必逐个重新导入。文件最多 32 MiB，单个样本的 8 MiB 和最多三份导入限制保持不变。

选择文件或取消不会改变当前比较；点击打开后替换当前导入集合与位置，内置城市保留。全部校验通过才应用，同名内置样本与程序不一致时停止打开。详细格式与兼容规则见 [比较项目格式与恢复](docs/比较项目格式与恢复.md)。

## 如何加入其他城区

点“管理样本”，选择城市纹理样本包 JSON，再点“加入左侧比较”。样本包同时包含道路、建筑、各自的下载框、原始查询、抓取时间、许可与原始数据 SHA-256；当前只接受声明为 OSM / ODbL 1.0 的数据。可先下载内置样本包了解格式。

文件在本地浏览器解析，不上传或执行。导入数据的真实性、许可和原始校验值为提供者声明，应用只校验格式、坐标、节点一致性、闭环、范围与资源上限，不验证原始数据哈希或完整多边形拓扑。刷新或关闭页面后可打开已保存的比较项目恢复，也可重新导入单个样本；分享视图参数时请附带同一份样本包。统计报告不含原始几何，不能当作样本包导入。详见 [样本包格式与导入](docs/样本包格式与导入.md)。

源码提供原始 Overpass JSON / JSON.gz 的离线转换工具，输出可导入 v0.4 或更新版本。转换时需要 Python 3.10+ 和 Node.js 22+；使用生成的样本包不需要安装依赖。先用既有真实快照演示：

```text
python scripts/转换城区样本.py --config examples/苏黎世离线转换.json --output .runtime/苏黎世-导入示例.json
```

示例是既有苏黎世快照，使用单独 ID 方便导入，不代表新增城市。其他城区的准备与来源要求见 [Overpass 离线转换](docs/Overpass离线转换.md)。

## 建筑轮廓怎么读

![仅建筑图层的真实截图](docs/建筑图层预览.png)

南京样本收录 350 个建筑轮廓要素，苏黎世收录 1,573 个，伯尔尼收录 1,359 个；这是下载范围内的总数，界面显示的是当前窗口中与其有正面积交集的数量。一个多边形关系可能包含多片轮廓，边界上的轮廓只计一次；全部落在内院里的观察窗口不会误计建筑。

图层切换改变画面，不改变道路筛选口径。仅建筑模式下仍显示独立的路网指标，界面和导出会标注。建筑数据不含高度，不是三维楼体，也不等于住房或人口分布。详见 [建筑数据说明](docs/建筑数据说明.md)。

## 先看一张观察卡

![由真实浏览器实际下载的观察卡](docs/双城观察卡.png)

地图中的虚线表示已收录的步行或骑行道路，其他道路按类别使用不同线宽。步行道开关同时影响地图和统计。南京新街口样本包含地下及室内通道；勾选步行道路时纳入统计，平面图不区分层级。密度可能受独立人行道、服务道路、分隔车道与 OSM 收录完整度影响，不宜直接拿来评价城市。

## 计算方法

道路坐标以城区中心投影到局部公里平面；按观察窗口裁剪线段，再以无向 OSM 节点对去重。总长与面积给出密度。方向折叠到 0–180° 后按 10° 分箱，以线段长度加权计算 Shannon 熵，并归一化到 0–100。

**方向多样性不是城市质量评分，也不能单独判断城市是否网格化。** 对分箱边界敏感，不同道路角度可能产生不同数值。详见 [方法与限制](docs/方法与限制.md)。

## 数据来源与可复核性

瑞士样本来自 [Swiss Overpass API](https://overpass.osm.ch/)，道路抓取于 2026-10-15 UTC，建筑抓取于 2026-10-16 UTC。南京新街口样本来自 [Overpass API](https://overpass-api.de/)，道路与建筑分别抓取于 2026-10-17 UTC，转换后有 433 条受支持道路、350 个建筑轮廓要素，7 个多边形关系和 5 个内环，无建筑跳过。样本中心使用 WGS84 坐标，靠近 [OSM 新街口站点](https://www.openstreetmap.org/node/7999205745)。

各批次独立保存原始查询、抓取时间、接口快照标识及 SHA-256。瑞士标识 `117749` / `117765` 不是日期；南京接口返回 ISO 时间形式的标识，也不等于本次抓取时间。不会将抓取时间宣称为地图数据的更新时间。

- `data/snapshots/`：三座城区各自的道路与建筑原始 Overpass JSON，共六份 gzip 归档。
- [道路来源清单](data/来源清单.json)、[建筑来源清单](data/建筑来源清单.json)：查询、时间和原始文件校验值。
- `dist/data/`：由原始数据转换出的浏览器样本。
- [数据许可](数据许可.md)：OpenStreetMap contributors / ODbL 1.0。

有 Python 3.10 或更新版本时，用自己的解释器运行：

```text
<Python解释器绝对路径> scripts/获取城市数据.py --offline
<Python解释器绝对路径> scripts/获取建筑数据.py --offline
```

脚本会校验归档并离线重建样本。仅使用 Python 标准库。去掉 `--offline` 时优先使用本地缓存；`--force` 才会重新请求公开接口。刷新后应同步归档与来源清单，避免混用不同版本的数据。

## 如何发布新版本

维护者同步更新 `package.json`、`.github/release.json`、使用说明和对应版本的发行说明，将版本清单合入 `main` 后启动发行流程。PR 阶段只检查和打包；主分支检查、发行 HTML 浏览器验证及附件回下载核对全部通过后，流程发布该版本。已有公开版本不会被覆盖。详见 [发行流程](docs/发行流程.md)。

## 原创与参考

界面、同尺度双城交互、Canvas 绘制、几何计算、报告与导出独立实现。参考了公开的道路展示与城市形态分析方法，未复制参考项目的源码、图片或地图预设。使用成熟方法不代表发明了这些算法。
