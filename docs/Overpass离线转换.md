# 将原始 Overpass 文件变成样本包

仓库中的通用转换工具读取本地 Overpass JSON 或 JSON.gz，将道路、建筑、来源记录组成 v1 样本包。转换结果可由已发布的城市纹理 v0.4 及后续兼容版本导入，不需要修改应用或内置城市列表。

转换需要完整的 **main 源码**、Python 3.10+ 和 Node.js 22+，不需要安装第三方包。Python 负责转换，Node 使用应用现有的校验器核对最终文件。普通使用者打开城市纹理或导入转换结果时，不需要安装这两个解释器。

工具完全离线：不会打开 `endpoint`、执行查询、自动下载地图或改写原始文件。它不是 GeoJSON 转换器，也不会验证来源声明的真实性。

## 先跑通已有真实快照

在仓库根目录执行（`python` 换为自己 Python 解释器的名称或绝对路径）：

```text
python scripts/转换城区样本.py --config examples/苏黎世离线转换.json --output .runtime/苏黎世-导入示例.json
```

成功后，在 v0.4 中点“管理样本”，选择生成的 JSON，再点“加入左侧比较”。它会显示为“苏黎世·导入示例”，可与内置苏黎世比较。

这是对仓库既有真实快照的转换演示，**不是新增城市或新抓取的数据**。示例保留 3,287 条受支持道路、1,573 个建筑轮廓、18 个多边形关系和 20 个内环，原始哈希与已归档来源一致。其 ID 与内置样本不同，便于实际测试导入与移除；同一地图数据重复导入不增加地理覆盖范围。

再次生成到同一路径会提示文件已存在。确认需要替换时加 `--overwrite`；校验失败时原输出保留。

## 换成自己的城区

复制示例配置，更新以下内容：

1. `city`：样本 ID、城市名、外文名、城区、国家或地区、中心经纬度、六位颜色值。字段要求沿用[样本包格式](样本包格式与导入.md)。
2. `roads.file`、`buildings.file`：各自的本地原始响应路径，支持 `.json` 和 `.json.gz`。相对路径以**配置文件所在目录**为基准，不以终端目录为基准。
3. 两份 `bbox`：原始查询的实际下载框，格式 `[南纬度, 西经度, 北纬度, 东经度]`。道路与建筑可来自不同批次、不同范围，但都必须覆盖所有观察尺度。
4. 两份 `source`：实际接口、原始查询、带时区的抓取时间和数据限制。原始 SHA-256 和快照标识的处理见下一节。

然后指定自己的配置和输出路径：

```text
python scripts/转换城区样本.py --config 我的配置.json --output 我的城区样本.json
```

道路响应应包含 `out geom` 产生的完整 way 节点 ID 与几何；建筑响应应包含闭合 way 或带成员几何的 multipolygon。需要内院和多边形关系时，仅下载建筑 way 不足以保留这些结构。

配置中的 `bbox` 不能从要素坐标最值推算：完整道路和建筑可能越出查询框，几何范围不等于已下载覆盖范围。工具核对查询中显式四数字框与配置是否一致，允许 7 位小数的舍入误差。可使用局部 `(南,西,北,东)` 或全局 `[bbox:南,西,北,东]`；只使用 area / around / poly 的范围无法通过此项检查。

这是对提供者声明的一致性检查，不是完整的 Overpass 查询解析器，也不证明该查询曾被执行、响应完整或地理范围真实。含 `remark` 错误提示的响应会被拒绝。

## 来源字段怎样填写

| 字段 | 转换行为 |
| --- | --- |
| `source.name / license / url` | 省略时分别采用 OpenStreetMap contributors、ODbL-1.0 和 OSM 版权页；最终仅接受应用支持的 OSM 来源声明 |
| `endpoint / query / fetchedAt / limitations` | 必须提供；不会用文件修改时间或当前时间冒充抓取时间 |
| `snapshotToken` | 优先从原始 `osm3s.timestamp_osm_base` 读取；同时提供声明时必须相同。响应缺少该字段时，需在配置中如实记录其标识状态，例如“接口未提供” |
| `rawSha256` | 对**解压后原始响应字节**计算 SHA-256；配置中有预期值时必须匹配，没有时记录计算结果。JSON 重排、换行或 BOM 都会影响原始哈希 |

转换器能证明生成包对应所选文件的字节内容，不能证明文件来自声明接口、抓取时间真实或许可声明成立。导入应用后仍显示“用户导入，来源声明未经应用核验”。

## 输出、限制与错误保护

输出为经过应用同一校验器规范化的纯 JSON，没有可执行脚本。道路按既有白名单筛选，坐标四舍五入到 7 位小数；未知 `highway` 类型计入终端的 `ignoredRoadWays`，不参与地图统计。

转换遇到无法闭合、缺少几何或无法唯一拼接的建筑时，默认停止并报告首个原因。如果已检查这些缺漏并希望保留其余数据，可加 `--allow-skipped-buildings`；所有跳过 ID 和原因都保留在样本的 `conversion.skipped` 和终端摘要中。不要把跳过建筑后的空白理解为当地没有建筑。

空的成功建筑响应可生成零建筑样本；道路至少需要一条受支持类型。重复 OSM 要素 ID、节点错位、非有限数值、重复 JSON 字段和损坏压缩文件会被拒绝。内院沿用既有拼接逻辑，不提供完整 GIS 拓扑证明或重叠求并集。

每份原始响应解压后最多 40 MiB、最多 50,000 要素和 1,000,000 个几何点；单段最多 4,096 点，单关系最多 1,024 成员。配置不超过 128 KiB。最终样本仍需满足应用的 8 MiB、200,000 点及其他限制；原始输入允许更大，是因为可能包含未选类型与重复出现在成员几何中的坐标。

输出默认不覆盖，`--overwrite` 也只在全部校验成功后原子替换。配置、道路原始文件和建筑原始文件均不能作为输出路径。Node 不在 PATH 时可用 `--node /解释器绝对路径` 指定。

## 开发验证

```text
python -m unittest discover -s tests -p "test_*.py"
npm test
```

CI 覆盖两个真实城区、普通/压缩 JSON 等价、原始哈希和标识不匹配、错误响应、范围声明、损坏输入、跳过记录及输出保护。浏览器任务会实际选择由转换器生成的文件，验证地图统计、来源显示和移除；发布任务也使用同一检查。
