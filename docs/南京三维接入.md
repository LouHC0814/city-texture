## 下载到本地后的准备

新增 scripts/准备南京模型.py，只使用 Python 标准库和仓库已有 Node.js 体检工具。它不访问网络，不改 dist，不更新版本或发布，结果放在忽略跟踪的 .runtime 下。

在仓库根目录运行以下命令；本机请用自己的解释器绝对路径：

```text
<Python解释器绝对路径> scripts/准备南京模型.py --input <下载原件.glb或.zip> --out .runtime/南京模型接入/紫峰首次检查 --node <Node解释器绝对路径>
```

默认来源声明是 tools/模型体检/南京紫峰-来源清单.json。处理其他模型时必须用 --source 指定属于该模型的来源 JSON，包含 model、author、license、licenseUrl、sourceUrl；程序记录提供者声明，不会自动鉴定文件身份或授权。

支持：

- GLB 原样保留；ZIP 内的 GLB 亦不重新导出。
- glTF 2.0 单个外部或 base64 buffer；相对路径的 PNG/JPEG 图片合并进 GLB。几何、材质、节点和原署名保留。
- ZIP 内嵌套目录、中文文件名和 URI 百分号编码；包内多个模型时须用 --entry 指定入口。
- 不解压 ZIP 到工作目录；限制压缩包大小、展开总量、条目数量；拒绝越界资源、网络 URI、重复路径、符号链接与加密条目。

范围：GLB 上限 64 MiB，包和资源总量 128 MiB，ZIP 最多 512 条，glTF JSON 上限 8 MiB。多 buffer 和带声明扩展的 glTF 暂不自动转换，不删除扩展以换取通过。直接 GLB 仍由现有体检规则给出 error / unsupported。

输出目录必须不存在，避免覆盖已有结果。转换或读写失败不提交结果目录；体检成功完成但候选不合格时，仍保留原件及错误报告。

结果包括：候选模型.glb、原始下载文件、来源声明.json、接入准备结果.json，以及体检目录中的 HTML / JSON / issues 三份报告。散装 glTF 的引用资源另保存在原始资源目录。接入准备结果记录原件、每个实际读取资源和 GLB 的 SHA-256、转换范围及状态。

退出码：0 静态体检通过；2 体检完成但候选有错误或不支持；3 准备、参数或读写失败。
