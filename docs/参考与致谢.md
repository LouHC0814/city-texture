# 参考与致谢

本项目为独立编写的城市形态观察原型。以下早期条目是方法或视觉层次参考，没有复制它们的业务代码、图片、地图预设或生成结果。v0.7 新增三维功能，Three.js 作为 MIT 运行库本地打包；SDC 模型按 CC BY 4.0 单独署名，见文末。

| 来源 | 参考的思路 | 本项目中的实现 |
| --- | --- | --- |
| [anvaka/city-roads](https://github.com/anvaka/city-roads) | 以道路为主要视觉元素，公开数据缓存减少等待 | 自己编写 Canvas 绘图、双城对照与本地样本加载 |
| [marceloprates/prettymaps](https://github.com/marceloprates/prettymaps) | 地图的视觉层次和克制的配色 | 自己设计纸色界面与道路分层；未使用源码、配色预设或图片 |
| [gboeing/osmnx](https://github.com/gboeing/osmnx) | 路网方向、长度加权与方向熵的分析方法 | 自己实现局部投影、线段裁剪、无向去重与固定分箱统计，公开与原库流程的差异 |
| [pysal/momepy](https://github.com/pysal/momepy) | 将城市形态转为可解释指标 | 选择少量可核验指标，避免综合优劣排名 |
| [MapLibre GL JS](https://github.com/maplibre/maplibre-gl-js) | 调研过的通用地图引擎候选 | 当前未引入，原型不依赖在线矢量瓦片 |

地图数据直接从 [Swiss Overpass API](https://overpass.osm.ch/) 和 [Overpass API（南京）](https://overpass-api.de/) 获取，归属于 OpenStreetMap contributors，遵循 [ODbL 1.0](https://opendatacommons.org/licenses/odbl/1-0/)。代码许可与数据许可分开，详见 [数据许可](../数据许可.md)。

方向熵是已有的统计方法，本项目不主张发明。中文交互、同尺度比较、观察卡与报告的产品组合及程序实现属于本项目的具体工作。

浏览器验证脚手架沿用作者已有的个人项目检查方式，并根据本项目的地图与数据行为调整；运行时没有第三方库。

## 2026-10-17 · 三维视角保存与恢复前的 GitHub 调研

| 检查或采用文件 | 可参考之处 | 本轮采用方式 |
| --- | --- | --- |
| [Three.js OrbitControls](https://github.com/mrdoob/three.js/blob/9b4a2ac29c63ccb43fd51c5661f2f873ac2c39b8/examples/jsm/controls/OrbitControls.js) 的 `saveState` / `reset` / `position0` / `target0` | 官方给出记录初始 spherical 与距离的入口；保存对象状态的标准方式 | 自己从 `camera.position` / `controls.target` 读取数值，写入独立 JSON；不在运行中改动 OrbitControls 内部状态，避免破坏后续交互 |
| [three.js editor camera-state serialization（commit 0a93a27）](https://github.com/mrdoob/three.js/blob/0a93a276c12d5fe71da31c45b3da2e95ce7af11d/editor/js/Sidebar.Object3D.js) | 同时记录 fov / near / far 与目标点，恢复时一次性重设投影矩阵 | 视角 JSON 同步保存 `fov / near / far`，应用时调用 `camera.updateProjectionMatrix()` 再 `controls.update()`，并立刻重新对准预设按钮 |
| [glTF 2.0 规范 §Camera](https://github.com/KhronosGroup/glTF/tree/main/specifications/2.0#camera) | 投影参数的取值约定（perspective 必有 yfov / znear / zfar） | 自行约束在 [10°, 90°] / [1e-3, 10] / (near+0.1, 10000]；与 glTF 默认范围一致，避免被误导成兼容 glTF |
| [Sketchfab 模型详情页 URL](https://sketchfab.com/3d-models/free-la-tour-eiffel-8553f94d06e24cb4b0fde1080f281674) | 公开三维资源通常带作者与许可字段，方便核对 | 视角文件仅携带 `modelId`；作者 / 许可存于运行期 `KNOWN_MODELS` 映射，写入时只比较模型 ID，跨模型视角被拒绝，防止把铁塔视角错位到别的模型上 |

沿用 v0.6 比较项目的本地 JSON 文件方式：选择文件仅预览，点击"打开这份视角"才一次性替换相机状态并重渲染；选择文件、取消和错误输入都不改变现有视角。模型与运行库仍以原许可单独记录。

## 模型体检工具整合（2026-10-19）

- 使用 [Khronos glTF 节点 schema](https://github.com/KhronosGroup/glTF/blob/main/specification/2.0/schema/node.schema.json) 复核节点矩阵、TRS、children 等声明；工具对深度、支持特性和资源大小另设明确边界，不宣称完成官方全规范校验。
- 预览沿用固定 Three.js 0.186.0 的 GLTFLoader、OrbitControls 和本地 ESM 文件；MIT 全文与逐文件哈希在 tools/模型体检/预览/vendor。
- 工具实现、实验和具体参考见 [工具支持范围](../tools/模型体检/实现参考与支持范围.md)；由 WorkBuddy 协作实现，Codex 独立验收后整合，并补齐包围盒中心/范围溢出检查。
- 基线复用仓库 dist/data/landmark-eiffel.js，离线解压后核对原固定字节数及 SHA-256。没有为本轮重新下载或接入新的南京模型。
