# 城市纹理样本包 v1

样本包是包含原始坐标和来源记录的 JSON 文件，供 v0.4 或更新版本离线导入。它与应用导出的统计报告不同；后者没有完整几何，不能用来重建地图。

## 使用与分享

打开“管理样本”，选择文件，再点“加入左侧比较”。成功后它出现在两侧城市列表中，左侧切换到该样本中心；尺度、图层和道路筛选沿用当前选择。错误输入保留原比较。已有 ID 不会被覆盖，内置样本不能移除。

最多同时导入 3 份，每份最多 8 MiB。所有处理在浏览器内完成；刷新、重新打开单文件或关闭页面后，可以打开 v0.6 的已保存比较项目一并恢复，也可以再次导入单个样本。“下载样本包”保存完整的道路、建筑和来源，方便再次打开或与视图参数一起分享。对方先导入同一份样本包，再恢复视图；v0.6 也可直接分享包含样本与视图的[比较项目](比较项目格式与恢复.md)。

可先下载内置南京、苏黎世或伯尔尼的样本包查看实际格式。同一 ID 只标识样本，不是内容哈希；分享时应确保对方使用的是同一个文件版本。导入后再导出会规范化字段、重算转换计数，不保证与输入文件逐字节一致。

## 顶层格式

以下仅展示结构，不是可直接导入的数据。实际文件中的省略内容必须由转换后的真实数据补全。

```json
{
  "format": "city-texture-sample",
  "version": 1,
  "city": {
    "id": "my-city-sample",
    "name": "城市中文名",
    "english": "CITY NAME",
    "district": "具体城区",
    "country": "国家或地区",
    "lon": 0,
    "lat": 0,
    "color": "#27776c",
    "bbox": [],
    "roads": [],
    "source": {}
  },
  "buildings": {
    "cityId": "my-city-sample",
    "bbox": [],
    "features": [],
    "conversion": { "skipped": [] },
    "source": {}
  }
}
```

## 字段与单位

| 字段 | 格式与要求 |
| --- | --- |
| `city.id` | 小写字母开头，后接小写字母、数字或短横线，最多 48 字符；保留 ID `constructor`、`prototype` 不可用 |
| `name / english / district / country` | 非空文本，上限分别为 24 / 48 / 60 / 32 个 JavaScript 字符单元；无控制字符 |
| `city.lon / lat` | WGS84，经度 ±180°、纬度 ±85°；作为局部公里投影中心 |
| `city.color` | 六位十六进制颜色，如 `#27776c` |
| `city.note` | 可选的样本说明，非空且最多 160 个 JavaScript 字符单元，无控制字符；v0.5 起在地图来源和 JSON 报告中显示。旧版忽略此字段，关键限制也应写入 `source.limitations` |
| 两处 `bbox` | `[南纬度, 西经度, 北纬度, 东经度]`，不跨日期变更线；各自需在中心四周覆盖至少 501.001 米，宽高各不超过 20 公里 |
| `roads` | 1–15,000 条，每条有 `id`、`type`、`nodes`、`points` |
| 道路 `id / nodes` | OSM way / node 正安全整数；way ID 唯一，同一 node ID 在所有道路中必须对应完全相同的坐标 |
| 道路 `type` | 原 OSM `highway` 类型；机动车和步行类型白名单见 `dist/core.js`。未知类型保留但不参与统计，至少有一条受支持类型 |
| 道路 `points` | `[经度, 纬度]` 数组，与 `nodes` 一一对应，每条 2–4,096 点 |
| `buildings.cityId` | 与 `city.id` 完全相同 |
| `features` | 0–10,000 个，每个有 `id`、`outers`、`inners`、`kind` |
| 建筑 `id` | 唯一的 `way/数字` 或 `relation/数字`，数字为最多 16 位的正整数文本 |
| `outers / inners` | 环数组；至少一个外环，内环可为空。环由 `[经度, 纬度]` 组成，首尾完全相同，至少 4 点且面积非零 |
| `kind` | 非空建筑类型文本，最多 80 字符，如 `yes`、`residential` |
| 建筑资源上限 | 单环最多 4,096 点；单要素最多 128 环、8,192 点；整个样本包道路和建筑合计最多 200,000 点 |
| 全部坐标 | 有限数值且在 WGS84 范围内；投影后相对中心的东/北坐标绝对值各不超过 25 公里，允许完整 OSM 要素超出下载框 |
| `conversion.skipped` | 转换器跳过记录数组；可为文本，或含文本 `id`、`reason` 的对象。计数 `featureCount / relations / innerRings` 在导入时重算 |

空建筑数组表示提供者声明没有收录建筑，应用不会据此推断当地没有建筑。

## 两份独立来源

道路与建筑各自必须包含 `source`，即使同日抓取也要分别记录。应用不会联网打开这些地址。

| 字段 | 要求 |
| --- | --- |
| `name` | 固定 `OpenStreetMap contributors` |
| `license` | 固定 `ODbL-1.0`；本版没有其他来源许可的处理流程 |
| `url` | 来源说明 HTTP(S) 地址，不含账号密码，最多 500 字符 |
| `endpoint` | 实际数据接口 HTTP(S) 地址，不含账号密码，最多 500 字符 |
| `query` | 非空原始查询文本，最多 12,000 字符，可换行 |
| `fetchedAt` | 可解析的日期时间，包含时区，如 `2026-10-17T02:00:00Z` |
| `snapshotToken` | 非空接口快照标识文本，最多 100 字符；形式因服务而异，不等于本次抓取时间 |
| `rawSha256` | 原始响应的 64 位十六进制 SHA-256 |
| `limitations` | 非空数据限制说明，最多 2,000 字符，可换行 |

应用只验证声明格式，不持有输入包对应的原始响应，无法重新计算其原始哈希，也不核实许可、抓取时间或数据真实性。导入样本统一标注“用户导入，来源声明未经应用核验”，该标注会写入统计报告与观察卡。

## 转换前提与当前限制

应用不直接读取原始 Overpass 或任意 GeoJSON。main 源码提供 `scripts/转换城区样本.py`，可将本地 Overpass JSON / JSON.gz 转成此格式；需要 Python 3.10+ 与 Node.js 22+，使用生成包无需安装依赖。完整步骤见 [Overpass 离线转换说明](https://github.com/LouHC0814/city-texture/blob/main/docs/Overpass离线转换.md)。既有 `获取城市数据.py` 和 `获取建筑数据.py` 仍用于重建内置归档。

转换器应确保多边形拓扑有效：内环属于正确外环，环不自交，多片轮廓满足既有计算口径。应用检查闭环和非零面积，但不实现完整 GIS 拓扑验证。重叠要素不求并集，建筑数字仍是轮廓要素数，不是楼栋数；路网指标也不用于城市质量评分。道路、建筑的实际下载范围必须如实填写，不能为了通过范围检查扩大 `bbox`。
