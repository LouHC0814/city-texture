# 使用说明（v0.5.0）

本目录是城市纹理项目的"离线 GLB 体检工具 + 离线预览页 + 性能测量"独立实验，与主项目源码分离，独立于主应用运行。

> 编写时间：2026-10-19（第三次返修）。本版相对 v0.4.0 的变化：
> ① 节点图改成**全图**校验（环/深度/多父，覆盖所有场景与未挂接节点）；
> ② 世界矩阵与逐顶点变换做有限性检查，包围盒改由准入产出，杜绝"pass 但包围盒为 null"；
> ③ bufferView 必须落在**逻辑 buffer** 内，材质 5 个 textureInfo 校验引用；
> ④ `vendor --verify` 改为只读，不再重写清单；
> ⑤ 性能输出删掉 canHit60/60Hz 余量，FPS 分位数改为按瞬时帧率分布正确计算。

## 0 准备

- Node.js 22+（已用 v22.22.2 验证）
- **不需要 `npm install`，交付包不含 `node_modules`**：所有代码只用 `node:` 内置模块
  - 预览页的 Three.js 已内嵌在 `预览/vendor/`（three@0.186.0，MIT），哈希清单见 `预览/vendor/MANIFEST.json`，许可见 `预览/vendor/LICENSE-third-party.txt`
  - 性能测量用 Node 22 内置 `WebSocket` 直连 Chrome DevTools Protocol，无第三方包
- 不联网；反例随工具保存，基线使用 scripts/准备基线.cjs 从仓库已有归档离线还原并核对固定 SHA-256

## 1 一键复跑

```powershell
$node = (Get-Command node).Source
$root = (Resolve-Path ".").Path  # 在 tools/模型体检 目录执行

# 0) 先还原并校验真实基线，再运行测试
& $node "$root/scripts/准备基线.cjs"
& $node "$root\tests\run.cjs"                 # 结构/准入/CLI/vendor，不需要浏览器
& $node "$root\tests\preview-admission.cjs"   # 浏览器回归，需要本机 Chrome

# 1) 生成 21 个程序化反例（不覆盖其他 8 个独立反例）
& $node "$root\lib\gen-fixtures.cjs"

# 2) 基线体检
& $node "$root\bin\gltf-inspect.cjs" --input "$root\基线\eiffel.glb" --out "$root\体检" `
        --name eiffel --overwrite --source "$root\基线\来源.json"

# 3) 反例体检（逐个文件，--overwrite 才会覆盖）
Get-ChildItem "$root\反例\*.glb" | ForEach-Object {
  & $node "$root\bin\gltf-inspect.cjs" --input $_.FullName --out "$root\体检" --name $_.BaseName --overwrite
}

# 4) 起本地服务（仅 127.0.0.1）
& $node "$root\lib\preview-server.cjs" 5173

# 5) 六轮性能测量（桌面×3 + 手机模拟×3 + 敏感性验证 + 断网复跑）
& $node "$root\measure\run-fps.cjs" --port 5173 --cdp 9333 --ms 10000 --warmup 1000 --rounds 3
```

也可以走 npm scripts：`npm test` / `npm run test:browser` / `npm run fixtures` / `npm run measure` / `npm run vendor:verify` / `npm run pack`。

## 2 命令行体检

```
node bin/gltf-inspect.cjs --input <glb> --out <dir> [--name <label>] [--source <json>] [--overwrite]

  --input      GLB 文件路径，必填；超过 64 MiB 会在**读取之前**按 stat 直接拒绝
  --out        输出目录（不存在会自动创建）
  --name       报告名（默认取 basename；不允许路径分隔符、..、点开头）
  --source     **只接受 JSON**（不是 txt）。字段建议：author / license / sourceUrl / note / credit
               传 txt 会以退出码 3 报 source_not_json
  --overwrite  允许替换已存在的同名产物（默认拒绝，原文件一个字节都不动）
```

输出三份，**同一批次原子提交**：

```
<out>/<name>.gltf-inspect.json
<out>/<name>.gltf-inspect.html
<out>/<name>.issues.json
```

退出码：

| 码 | 含义 |
| --- | --- |
| 0 | `status = pass`（可以带 warning） |
| 2 | `status = error` 或 `unsupported`（报告已写出，可进去看问题） |
| 3 | 参数错误（未知参数、缺值、`--source` 不是 JSON、`--name` 含路径） |
| 4 | 读写失败（原子提交已回滚，上一批产物保持原样） |

### 2.1 状态模型

报告里的 `status` 是唯一真相，只有三档：

| status | 含义 | CLI 退出 |
| --- | --- | --- |
| `pass` | 通过准入，所有指标已实算 | 0 |
| `error` | 容器/结构/引用/容量/数据/节点图/世界变换有问题 | 2 |
| `unsupported` | 结构合法，但用了首版不支持的特性（Draco、量化、sparse、skin、动画等） | 2 |

**不维护"哪些错误码算致命"的白名单**——任何 `severity=error` 或 `severity=unsupported` 的 issue 都会让 `status` 掉出 `pass`，CLI 必然非 0。

`status !== pass` 时，`geometry.*` 与 `bounds.computed` 一律为 `null` / `unknown`，不会输出"算了一半"的数字。

### 2.2 写入的原子性

1. 先检查目标：若目标路径是目录或不可写，**在动任何现有文件之前**就失败
2. 三份内容全部写成同目录临时文件
3. 旧的三份改名为备份
4. 逐个 `rename` 提交
5. 成功则删备份；任一步失败则回滚（删除新提交、恢复备份、清理临时）

→ 不会出现"JSON 换了、issues 还是上一批"的混合状态。

## 3 准入规则（唯一真源）

`lib/gltf-admission.js` 是**同一份文件**，被 CLI（`require`）与预览页（`<script src="/lib/gltf-admission.js">`）共用：

```js
const v = window.GLTFAdmission.check(bytes);   // 浏览器
const v = admission.check(bytes);              // Node
// v = { status, fatal, issues, json, binOffset, binLength,
//       accessors, bufferViews, parentOf, nodeOrder,
//       worldBounds: { computed, conservative, meshLocal } }
```

校验分三段，**前一段不过就不进下一段**：

1. **容器段**：magic / version / 总长度 / chunk 头 / JSON 解析 / JSON 顶层必须是对象
2. **结构段**：
   - 字段类型与整数性、引用范围（buffer / bufferView / accessor / mesh / material / texture / node.children / scene.nodes）
   - **bufferView 必须落在所属逻辑 `buffer.byteLength` 内**（BIN 只是物理上限；BIN 比 buffer 多 0–3 字节的对齐填充是合法的）
   - accessor 容量、byteStride、componentType/type 枚举
   - **材质 5 个 textureInfo**（baseColor / metallicRoughness / normal / occlusion / emissive）的形状、`index` 范围、`texCoord`
   - **全图节点校验**：所有场景 + 未挂接节点上的环、深度 > 32、**非法多父**
   - **世界矩阵合成**：父子逐级相乘，任一元素非有限即 error
3. **数据段**：真正读 BIN —— 索引 `< POSITION.count`、顶点全部有限、**逐顶点世界变换结果有限**，并顺带算出精确包围盒

首版支持范围（`SUPPORT`）：

- 容器 GLB 2.0，总长度字段必须等于实际字节数
- buffer 只取内嵌 BIN chunk（`data:` URI buffer 不支持）；image 只允许内嵌 bufferView 或 `data:` URI
- POSITION 必须 float32 VEC3；indices 必须 SCALAR 5121/5123/5125
- 扩展全部不放行（`KHR_draco_mesh_compression` / `KHR_mesh_quantization` / `EXT_meshopt_compression` …）
- 不支持 skins / animations / morphTargets / sparse accessor

### 3.1 合法与非法，别搞混

| 情形 | 结论 | 理由 |
| --- | --- | --- |
| 两个不同 node 引用同一个 mesh | **合法** | 实例化，不是多父 |
| 同一个 node 作为多个 scene 的根 | **合法** | 场景各自持有一份引用，不构成父边 |
| 同一个 child 出现在两个 node 的 `children` 里 | **非法** `E_NODE_MULTI_PARENT` | glTF 规定每个节点最多一个父 |
| 默认场景没问题、第二个场景里有环 | **非法** `E_NODE_CYCLE` | Three.js 会解析所有 scene |
| 父子 scale 各 1e308（输入都有限） | **非法** `E_WORLD_MATRIX_NON_FINITE` | 相乘溢出，包围盒必然失真 |
| 负缩放 | **合法** | 世界矩阵有限，包围盒按真实顶点镜像 |

## 4 预览页

`预览/index.html`：

- **加载前先过准入**：文件选择与 `?file=` 两条路径都先跑 `GLTFAdmission.check()`，`status !== pass` 就直接拒绝，**根本不会调用 GLTFLoader**，并在顶部红条 + 状态栏写清错误码；**原模型保持不变**
- **`?file=` 白名单**：只接受 `/glb/eiffel.glb` 与 `/glb/fixtures/*.glb`；`http(s)`、`data:`、`//`、`..`、`\`、绝对域名一律拒绝。**没有取得的模型不要加路由**，用「选择文件」
- **地面不穿模**：归一化后按模型真实最低点放置，地面在模型下方一点
- **计数分开**：面板同时给"模型几何三角面"与"场景实际渲染"（`renderer.info`，含地面），不混用
- **画布实测**：显示 CSS 尺寸、`canvas.width/height`、`drawingBuffer` 与 `renderer.getPixelRatio()`，不用 emulation 参数冒充
- **首帧指标**：`loadToFirstVisibleFrameMs` = 从开始读取到"模型第一个真正被呈现的帧"（连等两个 rAF）；其中 `readMs` / **`admissionMs`（准入单独计时）** / `parseMs`（GLTFLoader）/ `firstRenderMs` 分段给出，不混成一项
- **采样相机路线按时间驱动**：固定角速度（rad/ms），同一时刻任何帧率下角度相同
- 资源释放：切换模型前 dispose geometry / material / texture + `renderLists.dispose()`
- 依赖自检：启动时探活 8 个模块（含 `/lib/gltf-admission.js`），缺任何一个都红条提示

服务器路由白名单（`lib/preview-server.cjs`，只监听 127.0.0.1）：

```
/                        → 预览/index.html
/lib/gltf-admission.js   → lib/gltf-admission.js（与 CLI 同一份）
/vendor/**               → 预览/vendor/**（限 .js/.css/.json/.png/.svg，且 resolve 后仍在 vendor 内）
/glb/eiffel.glb          → 基线/eiffel.glb
/glb/fixtures/<名>.glb   → 反例/<名>.glb
/glb/list.json           → 清单
```

其余 404；`..`、`%2e%2e`、反斜杠、NUL → 400；非 GET/HEAD → 405。请求逐行写 `measure/access.log.jsonl`。

## 6 性能测量（`measure/run-fps.cjs`）

```
node measure/run-fps.cjs [选项]
  --port 5173     预览服务器端口（没起会自动拉起）
  --cdp 9333      Chrome 远程调试端口
  --ms 10000      每轮采样时长
  --warmup 1000   预热时长（不计入统计）
  --rounds 3      每档轮数（桌面 3 + 手机模拟 3 = 6 轮）
  --headless 1    1=headless=new（默认）；0=headful（本机会被节流到约 1 帧/秒，仅作对照）
```

产物：`measure/fps-raw.json`（每轮全部帧间隔 `rawDts`）、`fps-summary.json`、`net-audit.json`、`shots/*.png`。

**指标定义（v0.5.0 修正）**：

- `dtMs` 是主指标：`median / p05 / p95 / p99 / min / max / mean`，直接来自 rAF 间隔
- `fps.median` = `1000 / dtMs.median`
- `fps.p05 / p95 / p99` 是**逐帧瞬时帧率 `1000/dt_i` 分布**的分位数（不是 `1000/分位数`）。因为 `1000/x` 单调递减，`fps.p95 = 1000 / dtMs.p05`
- **不再输出** `canHit60` / `headroom60x` / `allCanHit60` / "全部可满 60fps" 这类判断：rAF 间隔不是 GPU 执行时间，比值不能当屏幕预算余量
- 计时精度约 0.1ms；帧时间中位 0.7ms 时瞬时帧率的相对误差可达 ±14%，所以 `fps` 的尾部只能当噪声量级参考

**这套数据的边界（写死在输出里，也会打印）**：

- 能证明：本机该 Chrome 配置下、该视口、该模型的 rAF 间隔与渲染吞吐；两种视口的相对差异；断网后仍可加载
- 不能证明：真实手机帧率、GPU 单帧耗时、主项目在真实 60Hz 屏幕上"够用"、把帧时间除以 16.67ms 得到的"余量"、其他浏览器/驱动
- `fps` 字段一律读作"rAF 吞吐"，不是屏幕帧率

本机注意：headful 窗口会被 Chrome 判定遮挡，rAF 被节流到约 1 帧/秒，数据不可用；默认走 `headless=new`（仍是真实 GPU）。

## 7 打包与第三方许可

```powershell
& $node "$root\scripts\sync-vendor.cjs" --verify   # 只读核对：7 个文件 vs 既有 MANIFEST，不符则非 0，不改任何文件
& $node "$root\scripts\pack.cjs"                   # 复制到 pack/城市纹理-模型体检实验/ 并出清单
```

两个模式是分开的：

| 命令 | 需要 node_modules | 会写文件 | 用途 |
| --- | --- | --- | --- |
| `sync-vendor.cjs` | 是（且校验 `three/package.json` 版本 === 0.186.0） | 覆盖 vendor + 重写 MANIFEST | **建立基准** |
| `sync-vendor.cjs --verify` | 否 | **绝不写** | **检查有没有被动过** |

`pack` 会排除 `node_modules`、`measure/.chrome-*`、`*.tmp-*`、`*.bak-*`、`.tmp-preview-server.*`，并在 `pack/MANIFEST.json` 里给出每个文件的 SHA-256；若仍发现临时文件会以退出码 3 报错。

## 8 已知边界

- 只处理 GLB 2.0 + 单 BIN chunk + 静态网格；`data:` URI buffer、稀疏 accessor、Draco/meshopt/量化、骨骼/动画/morph 一律 `unsupported`
- 父子变换场景下 GLB 自报 min/max 常与实算不一致，`W_BBOX_MISMATCH` 属信息性 warning，不影响 pass
- `bounds.computed` 是**逐顶点**世界范围，由准入计算；`bounds.conservative` 是本地 AABB 8 角点变换后的保守框，只用于快速剔除
- 手机档是 CDP 设备模拟，不是真机；渲染 DPR 被页面限制在 1.5，实际 canvas 尺寸见报告里的 `drawingBuffer`
- 真实手机触控、其他浏览器、真实 vsync、GPU timer、WebGL 失败回退、下载落盘仍未验证，见 `交付验收说明.md` §4
